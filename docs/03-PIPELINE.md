# 03 管线：这支片子是怎么被造出来的

> AARON 的必交材料之一是「工作流或系统架构图」。这一页就是那张图的文字版；
> `submission/pipeline.svg` 是给评委看的版本。

## 一句话

一张图版 = 一个镜头。六张生成式图版 + 一条时间轴 + 一套程序化叠加 + 一条调色曲线，
逐帧算出来，交给 ffmpeg 编码；所有参数集中在 `story.py` 一个文件里。

## 每一层为什么这么切

| 层 | 为什么独立 | 踩过的坑 |
| --- | --- | --- |
| `plates.py` | 图版处理一次就好，改运镜不该重跑图版 | 出图工具在右下角打水印；用亮度检测会把瓶身那张的亮雾当成水印，改成固定框 |
| `render.py` | 逐帧纯函数：给定帧号，输出同一张图 | 逐帧画字 + 逐帧高斯模糊吃掉三分之一时间，改成蒙版缓存 |
| `audio.py` | 声音和画面解耦，改画面不用重混音 | ffmpeg 的 loudnorm 单遍会过冲，改两遍（先量再归） |
| `assemble.py` | 拼接与混流放在最后一步 | 两个 ffmpeg 写同一个 mp4 会静默损坏；每段写自己的文件 |
| `verify.py` | 判据独立于实现 | 「看起来没问题」不是判据；每条都要能从成片里量出来 |

## 渲染成本（本机）

| 项 | 数值 |
| --- | --- |
| 单帧（含叠加与字幕） | ~0.25–0.9 s |
| 720 帧 | 约 7–8 分钟（分三段跑） |
| 编码 | h264 veryfast / CRF 21 / 10.9 Mbps |
| 成片 | 41.7 MB |

## 为什么不用文生视频

三个理由，按重量排：

1. **连续性**：这条片子的卖点是一次连续下坠。逐镜生成的视频模型保不住同一条岩缝的形。
   图版 + 运镜能保证「同一个空间」。
2. **可复现**：评委要的是「你怎么做的」。一个能一条命令重建的管线，比一段抽卡式的生成记录更有说服力，
   也正好对上 AARON 把「工作流」当作品的那一类（01 类）的价值观。
3. **预算**：本机没有出片通道（父单 11-03 已定：AIGC 出片要花钱开通道，不批）。

代价写在 `docs/06-RETRO.md`：运镜是 2.5D 的，贴得再近也骗不过一个盯着岩壁看的人。
